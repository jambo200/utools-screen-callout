# 屏幕标注插件 · Step 2：实施方案（可施工 / 可证伪 / 可评审）

> 已确认范围：**P0**；标注屏幕 = **光标所在屏（可配置固定屏）**；退出 = **默认清空（可配置保留）**。
>
> 本方案的目标不是「看起来完整」，而是：**照着文件清单能直接写代码；每条验收都能被判失败；评审时能逐条打勾**。

---

## 0. 方案摘要

| 项 | 决策 |
| --- | --- |
| 产品形态 | uTools 插件：`屏幕标注` 功能指令 → 全屏透明置顶覆盖层 + 悬浮标注工具栏 |
| 主界面定位 | `index.html` = 控制台/配置页 + 会话管理器；进入 `annotate` 时自动隐藏主窗口 |
| 覆盖层 | 单块显示器 → 一个 `BrowserWindow`（透明、无边框、置顶 `screen-saver`、全屏） |
| 技术栈 | 原生 HTML/CSS/JS，**无构建步骤**（Electron 下 `file://` 加载 ES Module 有兼容风险，故用经典 script + `window.SC` 命名空间） |
| 渲染 | 单张 `<canvas>` 全屏绘制，DIP 坐标，`devicePixelRatio` 缩放 |
| 状态 | 快照式撤销/重做（含图像引用分离） |
| 配置 | `utools.dbStorage`（官方定位：用户偏好/简单配置） |
| 放大镜 | 先选源区域 → 隐藏覆盖层 → `utools.captureDisplay({displayId})` → 裁剪 → 显示覆盖层 → 画镜片 |
| 验证 | Node 内置测试（纯逻辑）+ 静态检查 + **6 项 uTools 实机 Spike（阻断式）** + 人工验收矩阵 |

**为什么先做 Spike**：uTools 官方文档明确警告「主窗口隐藏后，插件应用可能按用户设定（默认 3 分钟）自动退出」。覆盖层必须在 30–60 分钟的演讲里存活；如果这条不成立，整个形态要重新决策。因此 S1 是**开发前置门槛**，不是上线前才测。

## 2. 架构

### 2.1 窗口与职责

```text
uTools Runtime
├─ 插件主界面（BrowserView）index.html
│   职责：配置 UI、启动/结束会话、读写配置、创建覆盖层窗口
│   运行：可能被隐藏（annotate 入口 mainHide + hideMainWindow）
│
├─ preload.js（主界面桥接，拥有全部本地能力）
│   职责：窗口生命周期、显示器枚举、captureDisplay、dbStorage、IPC 中枢、outPlugin
│
└─ 覆盖层（自定义 BrowserWindow）overlay.html —— 仅一块目标显示器
    职责：canvas 绘制、工具栏 UI、键盘快捷键、文本输入
    bridge：overlay-preload.js（只暴露必要接口，不含窗口管理）
```

关键约束（官方文档）：

- 自定义窗口「不支持 `BrowserWindow` 和 `webContents` 的实例事件监听」→ **不能用 `win.on('closed')`**，覆盖层退出必须自己 `sendToParent` 通知主界面。
- `closable: false` 会让 `window.close()` 失效 → 覆盖层保持 `closable: true`，关闭统一走「通知 + close」。
- 透明窗口要接收鼠标时，官方建议把 `backgroundColor` 设为近透明但非全透明（`rgba(255,255,255,0.01)`），按文档执行。

### 2.2 消息协议（IPC）

通道名统一前缀 `sc:`。主界面页与主 preload 同进程，直接调用；覆盖层经 `ipcRenderer` + `sendToParent`。

| 通道 | 方向 | 载荷 | 语义 |
| --- | --- | --- | --- |
| `sc:overlay-ready` | overlay → main | `{sessionId}` | 页面加载完成，请求初始化 |
| `sc:session-init` | main → overlay | `{sessionId, settings, display, platform}` | 下发配置、目标显示器（id/bounds/scaleFactor）、平台 |
| `sc:exit` | overlay → main | `{sessionId, reason}` | 用户主动退出（Esc/按钮） |
| `sc:passthrough` | overlay → main | `{sessionId, on}` | 请求进入/退出鼠标穿透 |
| `sc:passthrough-ack` | main → overlay | `{on}` | 穿透已生效（主侧已调用 `setIgnoreMouseEvents`） |
| `sc:restore` | main → overlay | `{sessionId}` | 全局快捷键再次触发，恢复交互 + 聚焦 |
| `sc:capture-source` | overlay → main | `{requestId, rectDip}` | 放大镜请求截取源区域 |
| `sc:capture-result` | main → overlay | `{requestId, dataUrl, imageWidth, imageHeight}` | 裁剪结果（失败时 `dataUrl:null` + `error`） |
| `sc:closed` | main → overlay | — | 主界面强制关闭（仅异常兜底） |

`sessionId = Date.now() + 随机串`；覆盖层丢弃 `sessionId` 不匹配的消息（防旧窗口串扰）。

### 2.3 生命周期状态机

```text
IDLE
 └─(onPluginEnter code=annotate 且 from=hotkey/panel，或点击“开始标注”)
     STARTING ── 创建窗口/等待 ready/下发 init ──▶ ACTIVE
ACTIVE ──(Esc或退出按钮)──▶ CLOSING ──(close+outPlugin)──▶ IDLE
ACTIVE ──(工具栏“穿透”)──▶ PASSIVE(鼠标穿透，工具栏隐藏)
PASSIVE ──(全局快捷键再次触发 = onPluginEnter)──▶ ACTIVE（恢复交互+聚焦）
ACTIVE/PASSIVE ──(onPluginEnter 但会话已存在)──▶ 不重复建窗，只恢复
```

> 入口策略（实现调整）：从搜索框/开发者工具进入（`from=main`）只展示配置页，不自动开始标注；只有全局快捷键/超级面板入口（`from=hotkey|panel`）才直接进入标注。

- 会话标志 `sessionActive` 保存在 **preload.js 模块作用域**（同一次插件进程内有效）。
- `onPluginOut(isKill)`：`isKill=true` 时清理标志；`false` 时保留（后台可快速恢复）。**不在此事件里关闭覆盖层**（文档明确警告）。

### 2.4 关键时序

**启动**

1. `onPluginEnter({code:'annotate'})` → 若 `sessionActive` 为 false：读配置 → `getAllDisplays()` → 定目标屏 → `createBrowserWindow('overlay.html', ...)`。
2. 窗口 `show:false` 创建；callback 中 `show()` + `setAlwaysOnTop(true,'screen-saver')` + `focus()`。
3. 覆盖层页面 ready → `sc:overlay-ready` → 主侧 `sc:session-init`。
4. 覆盖层初始化 canvas/工具栏，聚焦窗口；主界面此时 `utools.hideMainWindow()`（来自搜索框进入时）。

**放大镜取像素（关键时序）**

```text
overlay 拖动源框 → 松手 → sc:capture-source
main: win.hide() → await 120ms → captureDisplay({displayId})
      → 按比例裁剪 → toDataURL() → win.show()/置顶/focus()
      → sc:capture-result
overlay: 内容作为镜片图像绘制（镜片内不含工具栏/已画标注）
```

**穿透/恢复**

```text
overlay: sc:passthrough{on:true} → main: setIgnoreMouseEvents(true,{forward:true})
         → sc:passthrough-ack → overlay 隐藏工具栏
恢复：全局快捷键 → onPluginEnter → main: setIgnoreMouseEvents(false) + win.focus()
      → sc:restore → overlay 显示工具栏
```

> 如果 S2（热键再次触发不生效）失败：退化为「穿透时保留工具栏的穿透按钮区域不可用」不可行，需启用备用方案 B2（见 6.2），或把穿透降级为「隐藏工具栏但保留鼠标」。

### 3.4 坐标 / DPI / 裁剪

- 窗口按 **DIP** 创建（`display.bounds`）；canvas CSS 尺寸 = `window.innerWidth/innerHeight`，位图尺寸 = CSS × `devicePixelRatio`，`ctx.scale(dpr,dpr)` 后全部按 DIP 绘制。
- 放大镜裁剪：**不手算物理像素**，用截图像素与显示器 DIP 宽度的实际比例：

```js
const rx = imageWidth  / display.bounds.width;
const ry = imageHeight / display.bounds.height;
const crop = {
  x: Math.round(src.x * rx), y: Math.round(src.y * ry),
  width: Math.max(1, Math.round(src.w * rx)),
  height: Math.max(1, Math.round(src.h * ry))
};
// 越界时按图像 bounds 收敛后再 crop
```

### 3.5 工具栏规格

> 初版设计为「工具行 + 操作行」；本轮已升级为「主工具条 + 当前工具参数条」的两段式结构，以 3.10 为准。

- 位置：目标屏底部居中，`bottom: 24px`，圆角深色浮条，两行：
  - 第一行：工具按钮（主选按配置顺序）+「更多」按钮（次选弹出）
  - 第二行：撤销、重做、颜色、粗细、清空、隐藏工具栏、穿透、退出
- 按钮：36×36，内联 SVG 图标 + `title` 中文提示；当前工具高亮。
- 颜色弹层：预设色板 + `<input type="color">`；粗细弹层：`<input type="range">`。
- 点击工具栏/弹层不触发 canvas 绘制（DOM 在 canvas 之上，事件止于 toolbar 容器）。
- 穿透时整条工具栏隐藏；隐藏工具栏时只隐藏第一/二行，保留左上角 16×16 的呼吸提示点？——**P0 不留**，靠快捷键恢复（避免挡住演示内容）。

### 3.8 配置页规格（`index.html`）

单页分区（卡片式，高度 640）：

1. **开始**：快捷键状态（`getCmdHotKey("屏幕标注")`：已设置显示键位 / 未设置 → 「去设置」调 `redirectHotKeySetting("屏幕标注")`）；「开始标注」按钮。
2. **工具栏**：主选/次选两列，每行 工具名 + 上移/下移/移入另一区；「恢复默认」。
3. **外观**：共用颜色开关；默认颜色；色板（8 个色块，可增删/改色/恢复）；各工具默认参数在「工具」页签中逐项设置，并支持单工具重置。
4. **会话**：目标屏幕（鼠标所在屏/主显示器/枚举列表）；退出清空；启动隐藏工具栏；默认激活工具（默认不选中）。
5. **快捷键**：退出/隐藏工具栏/穿透三个键的按键捕获输入。
6. **自检**：运行 `selftest.js`（history/geometry/settings 断言），显示 `通过 x / 失败 y` 与失败项；不写死成功。
7. **关于**：版本、三步使用说明。

所有修改即时写 `dbStorage`（防抖 300ms），并提示「已保存」。启动会话时主界面读配置下发。

### 3.9 异常与健壮性

- 配置读取异常/结构不符 → `sanitizeSettings()` 回默认值，配置页顶部提示「配置已重置」。
- 目标屏已不存在 → 回退主显示器。
- 截屏失败 → 镜片不创建，工具栏 toast「截屏失败，请重试」。
- 覆盖层 5s 内未 ready → 关闭窗口并复用主界面提示（主界面可能隐藏，则写本地日志）。
- 会话中重复触发 → 不建第二个窗口。
- 退出时先 `clearOnExit` 决定是否清空（默认清空即销毁窗口即可），再 `window.close()`；主侧 `utools.outPlugin()`。

### 3.10 UI 实现补充（本轮调整）

- 工具栏改为两段式：**主工具条**（工具 + 操作）与**参数条**（当前工具的颜色、线型、箭头、填充、字号、序号类型、透明度、倍数等）。参数条按 `TOOL_OPTION_KEYS` 驱动，工具按钮带展开标记与悬停提示。
- 工具参数写入 `settings.toolOptions`，由覆盖层通过 `sc:tool-state` 上报、preload 合并保存；旧版 `widths/sizes` 会在读取时迁移。
- 配置页改为 8 个页签（常规 / 工具栏 / 工具 / 外观 / 快捷键 / 使用 / 日志 / 关于）；工具栏页签支持拖拽排序与跨区移动，右侧实时预览；工具页签按工具编辑默认参数，并支持单个/全部重置。
- 工具栏与配置页图标统一为一套 24 网格、1.6 描边的线性 SVG；覆盖层工具栏为浅色双条（主工具条在上、参数条在下），选中工具用浅灰底，单一钴蓝用于焦点、色环与文字工具标识。
- 鼠标穿透时工具栏保持可见，穿透按钮变蓝并切换图标；鼠标移到工具栏上时临时恢复鼠标响应，移出后恢复穿透；点击任意工具会先退出穿透再选中该工具。

### 6.1 风险表

| ID | 风险 | 概率 | 影响 | 观测点 | 处置 |
| --- | --- | --- | --- | --- | --- |
| R1 | 主窗口隐藏后插件自动退出（官方警告，默认 3 分钟） | 中 | 致命 | S1 | 6.2 |
| R2 | 会话中全局快捷键不触发 onPluginEnter | 中 | 穿透无法恢复 | S2 | B2 备用 |
| R3 | captureDisplay 捕获到覆盖层自身 | 高 | 放大镜穿帮 | S4 | 隐藏+等待；仍失败改用"预捕获帧" |
| R4 | 独占全屏应用无法被置顶 | 低-中 | 少数场景不可用 | S5 | 文档声明限制 |
| R5 | 4K 全屏 canvas 重绘卡顿 | 中 | 手感差 | D4 | 分层渲染/脏矩形，仅重绘变化区 |
| R6 | 多显示器混合 DPI 错位 | 中 | 副屏不可用 | S6 | 单屏 P0 保底，多屏修缺陷 |
| R7 | 双击/误触穿透后"回不来" | 中 | 体验差 | A7 | 恢复入口常驻提示 + 文档 |

### 6.2 若 S1 失败（自动退出）的备选，按优先级

1. **B1 存活窗口模型**：进入后再 `utools.showMainWindow()` 让主窗口保持"已显示"（被覆盖层完全遮住），观察是否阻止 `onPluginOut`；若成立，退出会话时再 `hideMainWindow()`。
2. **B2 独立恢复小窗**：覆盖层拆成「大穿透窗 + 44×44 交互小窗」，小窗常驻可点，穿透后点小窗恢复（不依赖热键重入）。
3. **B3 缩短会话**：每次进入为一次标注会话（≤3 分钟）——只适合短讲解，不满足长演讲，需你确认是否接受。
4. **B4 形态重议**：若上述都不可行，说明 uTools 当前机制不适合"长时间覆盖层"，需要重新评估产品形态（例如独立桌面应用）。**这一步会回到 Step 2 重新评审，不擅自改方向。**

> S1 是唯一可能推翻整个方案的风险，所以放在 P0-A，先花 1 小时验证，再投入其余开发。

### 6.3 可评审的取舍说明

- 为什么无构建：uTools 自定义窗口加载本地文件，ES Module 在 `file://` 下存在兼容不确定性；无构建也能避免你额外配置 Node 工具链，代价是代码用命名空间而非 import。
- 为什么单屏：多屏同时覆盖需要多窗口状态同步，P0 收益低风险高；配置页保留"指定屏"满足投影场景。
- 为什么整笔擦除：像素级擦除需要离屏遮罩与合成，P0 不做半成品；整笔擦除行为确定、可测试。
- 为什么放大镜用"瞬时截屏"而不是录屏流：录屏流会捕获覆盖层自身且性能开销大；静态帧对"放大看清细节"足够，已列为已知限制（内容变化后需重新拉放大镜）。
